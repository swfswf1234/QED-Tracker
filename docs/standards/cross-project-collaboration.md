# 跨项目协作规范

确认状态：已确认

治理对象：与 QED-Engine 根仓库（及 Axiom-Flow）的需求承接、评审、执行、验收回执与跨项目诊断纪律
依据：QED-Engine 根仓库 `docs/standards/cross-project-collaboration.md` 上游约定，适配需求接收方视角（[ADR 0004](../adr/0004-standards-governance-alignment.md)）
关联测试：无（流程治理，事实以双方 todo 与 Git 历史为准）

## 目的与边界

本标准是 QED-Tracker 参与跨项目协作的唯一事实源。三项目独立开发、独立部署；本项目作为
需求**接收方**，承接根仓库登记的请求（todo 中标注「需求方：QED-Engine REQ-xxx」的任务），
在自己仓库内执行并回执。根仓库侧的发起、登记与验收流程以根仓库同名标准为准，本文不复制。

适用范围：任何涉及服务端口（8901）、共享表（`qed_*`）、根 `.env` 变量、dataset 布局、
Axiom-Flow 消费面或根仓库前端联调的改动。纯本仓库内改动不适用，走
[文档治理规范](doc-governance.md)的任务与文档绑定流程。

## 强制规则

### 承接流程

1. **承接登记**：根仓库 todo 登记请求后，在**本仓库** `docs/trackers/todo.md` 建任务条目，
   任务列标注 `[跨项目]` 并写明需求方（REQ 编号）与设计/计划文档位置。
2. **设计评审**：变更涉及接口、端口、数据布局或契约时，在本仓库 `docs/plans/` 建设计讨论
   文档（至少声明：需求方、目标项目、接口面、评审方、执行方、验收标准），经用户评审后实施；
   确定的设计按 [ADR 0003](../adr/0003-pending-design-location.md) 迁入 `design/`。
3. **执行**：在本仓库内按自身 AGENTS.md 与门禁执行（谁收任务谁执行）。
4. **验收回执**：本仓库任务完成并关闭后，向根仓库 todo 回执证据：本仓库提交号 + 测试输出
   + 联调验收结果；根仓库侧登记由根仓库 agent 或用户完成。
5. **约束**：跨项目改动不得破坏独立性铁律——QED-Tracker 未启动时根仓库前端对话/展示正常，
   根仓库后端离线时本服务以本地默认配置降级运行。

### 变更规模分级

| 规模 | 判定 | 必须产出 |
| --- | --- | --- |
| 接口/契约级 | 协议、端口、字段、数据目录或配置事实源变化 | 本仓库计划文档 + 本仓库 todo + 根仓库登记（由需求方完成） |
| 文案/操作级 | 文档措辞、命令示例、默认值说明 | 仅 todo 登记，可并入其他任务 |

### 执行纪律

#### 本仓库 git 边界

- 本仓库的提交由用户明确要求后执行；未获明确要求不提交 git（与 AGENTS.md 完成门禁一致）。
- 根仓库 agent 在本仓库工作区的合法动作仅限：读取、创建/修改本仓库文档（plans/todo/指南）、
  **不产生代码改动、不执行本仓库 git 提交与推送**；误产生的代码改动由其在本仓库 todo 登记
  移交，本仓库审阅后自行处理。

#### subagent 派发合规

根仓库派发任务前先核对任务归属：属本仓库代码任务则必须走登记请求流程，不得绕过本仓库
todo 与计划直接派发写码。

#### 跨项目诊断纪律

跨项目问题诊断遵循**先只读排查，后登记请求**原则；禁止无证据归因。

**诊断三必查**（在本仓库登记对根仓库的反馈或回复诊断结论前完成）：

| 序号 | 必查项 | 方法 | 禁止行为 |
| --- | --- | --- | --- |
| 1 | 对方代码实际行为 | `grep` / `rg` 搜索对方仓库源码中相关函数的实际实现 | 凭记忆或假设断言对方"用了旧格式""没改" |
| 2 | 服务日志实际记录 | 查看相关时间窗口的 HTTP 状态码与错误体 | 凭错误描述推断日志内容 |
| 3 | 配置实际生效值 | 核查 `.env` / 环境变量 / 配置文件实际值与传播链路 | 假设对方配置与自己不同或已过时 |

**禁止无证据归因**：todo 证据列与跨项目回复必须包含实际日志片段、代码行号或配置值；
不得以「疑似」「可能」「估计」作为唯一依据。排查后仍无法确诊时，标注「待对方协助排查」
并附已排查证据。

**误判处理**：本仓库对根仓库请求的判定被回执为误判时，在 `completed.md` 对应条目记录
误判原因分析（哪些假设被证伪、真实现象是什么），作为后续同类诊断参考。

## 执行与门禁

- 涉及共享表（`qed_*`）写权限、端口或根 `.env` 变量的改动，先核对根仓库
  `docs/design/` 契约文档与[共享表设计](../architecture/shared-tables.md)写权限表
  （文档归属与维护方为本仓库，根仓库经 `database-design.md` 登记同步，
  见 [ADR 0005](../adr/0005-shared-tables-doc-location.md)），不得单方面变更跨项目契约；
  契约变化由需求方发起并经用户裁决。
- 请求被拒或改期时，本仓库 todo 条目标注原因并保持与根仓库登记一致。
- 回执要素（提交号、门禁输出、联调结果）齐全后方可视为跨项目任务关闭。

## 变更与取代

改变承接流程、变更分级或执行纪律时必须先新增 ADR。措辞、链接和不改变语义的整理可直接
修改本标准。
