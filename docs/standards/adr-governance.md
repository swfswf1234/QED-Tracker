# ADR 治理规范

状态：Current
最后更新：2026-08-04
治理对象：ADR 准入、编号、元数据、状态、取代关系与归档路径
依据：QED-Engine 根仓库 `docs/standards/adr-governance.md` 治理模式
关联测试：`tests/test_documentation.py`（链接与元数据守护）

## 目的与边界

本标准规定 QED-Tracker 哪些决定必须使用 ADR，以及 ADR 如何编号、流转、取代和登记。
架构文档描述当前结构，设计文档描述接口与验收，计划描述实施步骤；ADR 只保存决定、理由和
长期后果。子项目 ADR 独立编号，不参与根仓库全局编号。

## 强制规则

### 准入

改变系统边界、公开 API、持久化语义、事实来源、跨服务契约、端口与部署拓扑或 standards 实质
规则时必须新增 ADR。实现细节、操作步骤和不改变语义的文档整理不得单独建立 ADR。

### 编号与路径

- 文件名固定为 `NNNN-lowercase-slug.md`，编号单调递增且进入主分支后永不复用。
- Proposed 和 Accepted 位于 `docs/adr/`；Rejected 和 Superseded 位于 `docs/history/adr/`。
- 新 ADR 使用当前最大编号加一，并在同一变更登记 `docs/adr/index.md`。

### 元数据与状态

每份 ADR 在标题后依次声明 `状态`、`日期`、`领域`、`决策阶段`、`取代`、`被取代`。

- 状态只允许 `Proposed`、`Accepted`、`Rejected`、`Superseded`。
- 领域只允许 `工程治理`、`API 与任务`、`数据与持久化`、`架构与边界`、`质量与评测`。
- 决策阶段使用 `v<主版本>.<次版本>`。
- 没有取代关系时写 `—`；存在关系时使用指向实际文件的 `ADR NNNN` Markdown 链接。

### 章节

每份 ADR 使用统一章节：`## 背景`、`## 决定`、`## 后果`、`## 关联`。`## 关联` 列出现有标准、
测试、设计与 ADR 链接，不复制其正文。

## 执行与门禁

1. 按本标准创建 Proposed ADR，分配下一编号并登记 ADR index。
2. 依次写入 `背景`、`决定`、`后果`、`关联`。
3. 接受或拒绝后同步状态、索引与关联文档。
4. 完整取代时同步双向元数据并把旧 ADR 移入 `docs/history/adr/`。

## 变更与取代

Accepted ADR 正文不得静默改写。允许修复失效链接、补充反向取代元数据或增加明确勘误；任何新
决定必须新增 ADR。修改本标准的准入、编号、状态、取代或归档规则时同样先新增 ADR。
